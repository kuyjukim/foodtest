# 오늘 뭐 먹지?

집에 있는 재료를 담으면, 지금 만들 수 있는 요리를 찾아주는 앱입니다.
레시피 **125개(요리 76종)** 를 앱 안에 가지고 있어서 인터넷 연결이나 API 키 없이 동작합니다.
휴대폰에 **설치해서 오프라인으로** 쓸 수 있습니다.

## 실행

배포된 주소는 **https://recipe.eliteaja.com** 입니다.
로컬에서는 `index.html` 을 브라우저로 열면 바로 쓸 수 있습니다. 빌드 과정도, 설치할 패키지도 없습니다.

앱으로 설치하려면 http 로 띄워야 합니다. (서비스워커가 `file://` 에서는 동작하지 않습니다)

```bash
python3 -m http.server 8000
# http://localhost:8000
```

안드로이드 크롬에서는 오른쪽 위 **앱 설치** 버튼이, 아이폰 사파리에서는 공유 → **홈 화면에 추가** 가 나옵니다.
설치하면 홈 화면 아이콘으로 열리고 주소창 없이 전체화면으로 뜨며, 비행기 모드에서도 레시피를 볼 수 있습니다.

## 어떻게 찾아주나

레시피마다 재료를 두 가지로 나눠 두었습니다.

- **필수 재료** — 없으면 그 요리라고 부를 수 없는 재료
- **있으면 더 좋은 재료** — 없어도 만들 수 있는 재료

필수 재료 상태에 따라 요리를 세 가지로 나눠 보여줍니다.

| 표시 | 뜻 |
| --- | --- |
| **바로 가능** | 필수 재료가 전부 있다 |
| **대체하면 가능** | 없는 재료를 가진 재료로 대신할 수 있다 |
| **N가지 부족** | 대체할 것도 없다 |

### 재료 이름 맞추기

| 방식 | 뜻 | 예 |
| --- | --- | --- |
| 별칭 | 같은 재료의 다른 이름 | `달걀` → `계란`, `파르메산` → `파마산치즈` |
| 범주 | 구체적인 재료는 큰 범주도 가진 것으로 침 | `삼겹살` → `돼지고기`, `묵은지` → `김치` |
| 같은 것 | 서로 바꿔도 차이가 없는 묶음 | `부침가루` ↔ `밀가루`, `국간장` ↔ `간장` |

### 대체 재료

위의 ‘같은 것’과 달리, **맛이 달라지지만 대신 쓸 수 있는** 재료는 따로 다룹니다.
바로 가능으로 섞지 않고 `대체하면 가능`으로 구분해서 보여주고, 상세 화면에 무엇으로 바꿀 수 있는지와
그러면 맛이 어떻게 달라지는지를 적어 둡니다.

```
돼지고기 대신  [소고기 ✓]  [닭고기]  [두부 ✓]
               기름이 적어 담백해진다
```

재료 두 개를 합쳐야 대체되는 경우도 있습니다. 예를 들어 고추장이 없으면
`고춧가루 + 된장 + 설탕` 세 가지를 모두 가지고 있을 때만 대체로 인정합니다.

요리 자체가 바뀌어 버리는 것(식빵 대신 밥 같은)은 대체로 치지 않습니다.

**그 요리를 그 요리이게 하는 재료는 대체하지 않습니다.** 오징어 없는 오징어볶음,
감자 없는 감자탕은 다른 음식입니다. 두 가지로 막습니다.

1. 요리 이름에 재료가 들어 있으면 자동으로 제외 (오징어볶음·감자탕·콩나물국·떡국 …)
2. 이름만으로는 안 드러나는 경우는 레시피에 `defining` 으로 명시
   (삼계탕의 닭고기, 육개장의 소고기, 제육볶음의 돼지고기, 북엇국의 북어 …)

반대로 다진 고기를 쓰는 동그랑땡·마파두부처럼 바꿔도 되는 곳에서는 그대로 제안합니다.

### 요리별 여러 버전

같은 요리라도 집에 있는 재료에 따라 만드는 법이 다릅니다.
김치찌개는 돼지고기·참치·스팸·꽁치·들기름 **5가지 버전**이 들어 있고,
가진 재료로 가장 잘 맞는 버전이 대표로 올라옵니다. 상세 화면의 탭으로 버전을 바꿔 볼 수 있고,
탭 색깔이 그 버전을 지금 만들 수 있는지(초록=바로, 파랑=대체) 알려 줍니다.

버전이 여러 개인 요리: 전 7종, 국수·토스트 6종, 김치찌개·볶음밥·파스타·덮밥 5종,
떡볶이·라면 4종, 된장찌개·떡국 3종,
냉면·김밥·죽·장조림·순두부찌개·제육볶음·계란찜 2종.

### 기본 양념

소금·설탕·간장 같은 **기본 양념 15가지는 집에 있다고 가정**합니다.
없는 양념은 왼쪽 패널에서 체크를 해제하면 결과에 바로 반영됩니다.

**처음 온 사람에게는** 기본 양념 칸이 펼쳐진 채로 "집에 없는 양념은 꺼 달라"는 안내가
한 번 뜹니다. 양념을 미리 꺼 두는 쪽도 검토했지만, 고춧가루·다진마늘처럼 한국 집에
거의 다 있는 것까지 끄면 김치+돼지고기에 김치찌개가 안 나오는 식으로 결과가
크게 줄어듭니다(4종 → 1종). 낙관적으로 보여주고 직접 끄게 하는 쪽을 택했습니다.

안내는 확인을 누르거나 양념을 직접 건드리면 다시 뜨지 않습니다.

담은 재료와 양념 설정, 화면 테마는 브라우저에 저장되어 다음에 열어도 그대로 남습니다.

## 쿠팡 파트너스 (장보기 링크)

부족한 재료를 상세 화면 맨 아래 **장보기** 칸에 모아서 쿠팡 링크로 내보냅니다.
필수 재료와 선택 재료를 나눠서 보여주고, 대체해서 만들 수 있는 재료는 살 필요가 없으니 빼 둡니다.

### 설정

`data/affiliate.js` 의 `partnerId` 한 줄만 채우면 됩니다.

```js
partnerId: 'AF1234567',   // partners.coupang.com 우측 상단 아이디
```

비워 두면 추적 없는 일반 쿠팡 검색으로 나가고 수수료 고지 문구도 뜨지 않습니다.
(제휴 관계가 없으니 고지할 것도 없음) 아이디를 넣는 순간 추적 태그가 붙고 고지 문구가 자동으로 켜집니다.
`enabled: false` 로 두면 장보기 칸 자체가 사라집니다.

### 링크를 고르는 순서

재료 하나당 링크 후보가 셋이고, 수수료 추적이 확실한 쪽부터 씁니다.

| 순위 | 출처 | 추적 | 만드는 법 |
| --- | --- | --- | --- |
| 1 | `affiliate.js` 의 `links` | 확실함 | 파트너스에서 손으로 생성 |
| 2 | `data/coupang-links.js` | 확실함 | **Open API 로 자동 생성** (아래) |
| 3 | 검색 링크 | 보장 못 함 | 자동. 위 둘이 없을 때만 |

검색 링크(`쿠팡 검색 주소 + lptag`)는 쿠팡이 공식 안내하는 방식이 아니라서
수수료가 안 잡힐 수 있습니다. 자동 생성을 한 번 돌려두면 대부분의 재료가 2번으로 올라갑니다.

### Open API 로 딥링크 자동 생성

`tools/gen-coupang-links.js` 가 재료 122개의 쿠팡 검색 주소를
파트너스 Open API 에 넣어 `link.coupang.com/a/...` 딥링크로 바꿔
`data/coupang-links.js` 에 저장합니다.

**왜 브라우저에서 직접 부르지 않나** — Open API 는 SECRET KEY 로 HMAC 서명을 요구합니다.
이 앱은 서버가 없는 정적 사이트라서, 브라우저에서 API 를 부르려면 비밀키를 소스에
넣어야 하고 그 순간 전 세계에 공개됩니다. 그래서 **배포할 때 한 번** GitHub Actions
러너에서 링크를 만들어 파일로 떨어뜨리고, 브라우저는 그 결과만 읽습니다.
비밀키는 GitHub Secrets 에만 있고 배포되는 파일에는 들어가지 않습니다.

**설정**

1. 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서
   두 개를 등록합니다.

   | 이름 | 값 |
   | --- | --- |
   | `COUPANG_ACCESS_KEY` | 파트너스 Open API 의 ACCESS KEY |
   | `COUPANG_SECRET_KEY` | SECRET KEY |

   키는 https://partners.coupang.com/#help/open-api 에서 발급합니다.

2. **Actions 탭 → '쿠팡 딥링크 생성' → Run workflow**

   링크를 받아 `data/coupang-links.js` 에 쓰고, 서비스워커 캐시 버전을 올려
   커밋한 뒤 **배포까지 같은 잡에서 끝냅니다.**

   배포를 따로 떼지 않은 이유가 있습니다. 워크플로가 `GITHUB_TOKEN` 으로 푸시한
   커밋은 다른 워크플로를 트리거하지 않습니다. 배포를 push 이벤트에 맡기면
   링크만 저장소에 들어가고 사이트에는 반영되지 않습니다.

**무엇이 링크로 바뀌나** — 재료별 **검색 결과 페이지**입니다. 특정 상품이 아닙니다.
`돼지고기` 를 누르면 '돼지고기 앞다리살' 검색 결과로 들어가고, 거기서 무엇을 사든
쿠키 유효 기간 안이면 수수료 대상이 됩니다. 검색어가 엉뚱해지는 재료 31개는
`searchTerms` 에서 미리 바로잡아 뒀습니다 (`밥` → 즉석밥, `배` → 배 과일).

### 상품 정보까지 (선택)

같은 워크플로의 **상품 정보 생성** 단계가 상품검색 API 로 재료별 실제 상품을
가져와 `data/coupang-products.js` 에 저장합니다. 장보기 칸에서 **없는 필수 재료**는
상품명·가격·이미지·로켓배송 여부가 담긴 카드로 바뀌고, 누르면 검색이 아니라
그 상품으로 바로 갑니다. 상품을 못 찾은 재료는 기존 링크 칩으로 남습니다.

**어떤 상품을 고르나** — 검색 1위를 그냥 쓰면 대용량·도매 상품이 걸립니다
(마늘 20kg 15만원). 집에서 한 끼 하려는 사람에게 맞지 않습니다. 그렇다고 최저가를
고르면 반대로 지나치게 작은 소포장이 걸립니다. 그래서 후보 10개를 받아 로켓배송을
우선하고 그중 **가격 중앙값**에 해당하는 상품을 고릅니다.
(`CANDIDATES`, `PER_INGREDIENT` 환경변수로 조정)

가격은 생성 시점의 값이라 화면에 기준일을 함께 표시합니다. 가끔 다시 돌려 주세요.
상품이 필요 없으면 Run workflow 에서 `products` 체크를 끄면 됩니다.

재료가 늘었을 때 다시 돌리면 새 재료만 추가됩니다.
로컬에서 대상 목록만 확인하려면:

```bash
DRY_RUN=1 node tools/gen-coupang-links.js
```

**키 관리** — ACCESS/SECRET KEY 는 코드나 커밋에 절대 넣지 마세요.
어딘가에 노출됐다면 파트너스 콘솔에서 재발급하고 Secrets 를 갱신하면 됩니다.

재료 이름 그대로 검색하면 엉뚱한 게 나오는 경우(`밥` → 밥솥, `배` → 선박)는
`searchTerms` 에서 바로잡습니다. 33개를 미리 넣어 뒀고 더 추가할 수 있습니다.

### 고지 문구

`disclosure` 의 문구는 공정거래위원회 추천·보증 심사지침과 쿠팡 파트너스 약관이 요구하는
것이라 **지우면 안 됩니다.** 링크가 보이는 화면(상세의 장보기 칸, 화면 맨 아래)에
항상 함께 나오도록 되어 있습니다.

링크에는 `rel="nofollow sponsored noopener"` 가 붙고 새 탭으로 열립니다.
`noreferrer` 는 일부러 넣지 않았습니다. 리퍼러 헤더까지 지워져 제휴 유입 출처 확인에
불리하기 때문입니다. `noopener` 만으로도 탭내빙은 막힙니다.

### 수수료가 잡히는지 확인하는 법

코드가 링크를 내보내는 것과, 쿠팡이 그 클릭을 수수료로 인정하는 것은 별개입니다.
다음 순서로 직접 확인하세요.

1. 파트너스에서 **채널(사이트) 등록과 승인**을 먼저 끝냅니다. 승인 전 클릭은 집계되지 않습니다.
2. 배포된 사이트를 열어 장보기 링크를 **직접 클릭**합니다.
3. 파트너스 → **리포트 → 실적/클릭** 에서 그 클릭이 잡혔는지 봅니다.
   (집계에 수십 분에서 하루가 걸릴 수 있습니다)
4. 클릭이 안 잡히면 검색 링크 방식이 추적되지 않는다는 뜻이므로,
   위의 딥링크 생성 워크플로를 돌려 2번 방식으로 올리세요.

## 온라인에 올리기

쿠팡 파트너스는 공개된 사이트가 있어야 의미가 있고, 서비스워커(오프라인·앱 설치)도
HTTPS 에서만 동작합니다. GitHub Pages 설정이 들어 있습니다.

1. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 바꿉니다.
   이 한 번은 손으로 해야 합니다. 워크플로 토큰에는 Pages 를 켤 권한이 없어서
   꺼진 상태로 배포하면 `Get Pages site failed` 로 실패합니다.
2. 그 뒤로는 `main` 에 푸시될 때마다 `.github/workflows/deploy.yml` 이 알아서 배포합니다.
   이미 푸시해 둔 상태라면 Actions 탭에서 **Re-run jobs** 를 누르면 됩니다.

주소: **https://recipe.eliteaja.com** (`kuyjukim.github.io/foodtest/` 는 이쪽으로 넘어갑니다)
저장소 이름이 경로로 붙지만 앱의 모든 경로가 상대 경로라 그대로 동작합니다.
(manifest 의 `start_url`·`scope`, 서비스워커 범위, 캐시 모두 그 폴더 안으로 잡힙니다)

### 자체 도메인 붙이기

**순서를 지켜야 합니다.** 저장소에 `CNAME` 파일을 먼저 올리면 GitHub 이 바로
그 도메인으로 리다이렉트를 시작하는데, DNS 가 아직 없으면 사이트에 아무도
접속할 수 없게 됩니다.

1. **DNS 먼저** — 도메인 관리 화면에서 `CNAME` 레코드를 추가합니다.

   | 타입 | 이름(호스트) | 값 |
   | --- | --- | --- |
   | CNAME | `recipe` | `kuyjukim.github.io` |

   값 끝에 점(`.`)을 요구하는 업체도 있습니다. 전파에 보통 몇 분 걸립니다.

2. 전파 확인: `dig recipe.eliteaja.com +short` 가 `kuyjukim.github.io` 를 가리키면 완료.

3. **그다음** 저장소 루트에 `CNAME` 파일(내용 한 줄: `recipe.eliteaja.com`)을
   올리고 푸시합니다. Settings → Pages 의 Custom domain 이 자동으로 채워집니다.
   (이 저장소는 완료된 상태입니다)

4. **Enforce HTTPS** 체크. 인증서 발급에 몇 분에서 한 시간쯤 걸립니다.

도메인을 붙이면 주소가 `/foodtest/` 하위가 아니라 루트가 되므로 경로가 더 단순해집니다.
앱의 모든 경로가 상대 경로라 코드 수정은 필요 없습니다.

## 검색·공유 (마케팅 기반)

앱이 한 페이지라 레시피 125개가 전부 같은 주소였습니다. 그래서 카카오톡 공유에
미리보기가 안 뜨고, 검색엔진에 '김치찌개' 로 걸릴 페이지도 없었습니다.

**레시피별 정적 페이지** — `tools/gen-pages.js` 가 `recipe/<id>.html` 125개를 뽑습니다.
본문이 HTML 에 그대로 들어 있어 자바스크립트를 실행하지 않는 크롤러도 읽습니다.
배포할 때마다 자동으로 다시 생성되므로 레시피를 고치면 따로 할 일이 없습니다.

- **Recipe 구조화 데이터(JSON-LD)** — 구글 레시피 검색의 카드에 들어가기 위한 것.
  조리시간은 ISO 8601(`PT25M`), 인분·재료·단계·분류를 담습니다.
- **OG 태그** — 카카오톡·페이스북에 공유하면 제목·설명·이미지가 뜹니다 (`og.png`).
- **sitemap.xml / robots.txt** — 126개 주소를 색인하도록 안내합니다.
  robots 에는 네이버(Yeti)·구글·다음 크롤러를 따로 허용해 두었습니다.

### 크롤러가 읽을 거리

앱 첫 화면은 자바스크립트로 그려서, 크롤러가 읽을 글자가 320자(대부분 버튼 이름)뿐이었습니다.
레시피 125개로 들어가는 길도 sitemap 말고는 없었습니다. 세 가지로 메웠습니다.

- **`recipes.html`** — 125개를 종류별로 묶은 목록. 재료·조리시간이 HTML 로 들어 있고
  `CollectionPage` + `ItemList` 구조화 데이터를 답니다.
- **첫 화면 아래 설명과 링크** — 사이트 설명, 종류별 개수, 자주 찾는 요리 12개,
  전체 목록으로 가는 링크. 사람이 스크롤 끝에서 읽어도 쓸모 있게 썼습니다. (320자 → 660자)
- **`llms.txt`** — AI 검색·답변 서비스용. 사이트가 무엇이고 어떤 레시피가 있는지,
  재료와 대체 규칙까지 평문으로 적습니다. 아직 표준은 아니지만 비용이 거의 없습니다.

`robots.txt` 에는 네이버(Yeti)·구글·다음에 더해 **GPTBot·ClaudeBot·PerplexityBot·
Google-Extended** 를 명시해 허용합니다. AI 답변에 인용될 때 출처로 노출되기 때문입니다.
원하지 않으면 `tools/gen-pages.js` 의 robots 부분에서 `Allow` 를 `Disallow` 로 바꾸면 됩니다.

### 검색엔진에 사이트 등록

소유확인 코드는 `site-verify.json` 에 넣습니다. 비어 있으면 태그를 넣지 않습니다.

```json
{ "naver": "발급받은코드", "google": "발급받은코드" }
```

값을 채우고 푸시하면 배포할 때 `index.html` 과 레시피 페이지 125개에 자동으로 박힙니다.
(크롤러는 자바스크립트를 실행하지 않으므로 HTML 에 직접 들어가야 합니다)

- **네이버** — searchadvisor.naver.com → 웹마스터도구 → 사이트 등록 →
  HTML 태그 방식의 `content` 값. 확인 후 **요청 → 사이트맵 제출** 에
  `https://recipe.eliteaja.com/sitemap.xml` 을 넣습니다.
- **구글** — search.google.com/search-console → 속성 추가 → HTML 태그 방식.
  확인 후 Sitemaps 에 같은 주소를 제출합니다.

**레시피별 주소** — 앱에서 레시피를 열면 주소가 `?r=kimchi-jjigae` 로 바뀝니다.
그 주소를 공유하면 해당 레시피가 열린 채로 뜨고, 뒤로가기로 닫힙니다.
정적 페이지의 '내 재료로 만들 수 있는지 보기' 도 이 주소로 들어옵니다.

**레시피별 공유 이미지** — `tools/gen-og-images.js` 가 레시피마다 이름·조리시간·재료가
담긴 카드를 뽑습니다(`og/<id>.png`, 장당 약 30KB). 카카오톡에 감자탕을 공유하면
감자탕 카드가 뜹니다.

매 배포마다 돌리기엔 느려서 **레시피가 바뀌었을 때만 손으로** 돌립니다.

```bash
node tools/gen-og-images.js          # 전부
node tools/gen-og-images.js japchae  # 하나만, 모양 확인용
```

이미지가 없는 레시피는 기본 `og.png` 로 자동으로 넘어가므로, 중간에 멈춰도
페이지가 깨지지 않습니다.

## 측정

`data/analytics.js` 에 토큰을 넣으면 켜집니다. 비어 있으면 스크립트를 아예
불러오지 않고 쿠키도 만들지 않습니다.

GA4 태그는 **빌드할 때 HTML 에 직접 박힙니다.** 레시피 페이지 125개는 `app.js` 를
부르지 않아서, 앱에서 넣는 방식으로는 검색·공유로 들어온 방문이 통째로 빠집니다.
그래서 `tools/gen-pages.js` 가 `index.html` 과 레시피 페이지 전부에 넣습니다.
앱은 이미 들어가 있으면 다시 넣지 않습니다 (중복 집계 방지).

끄려면 설정을 비우고 **다시 배포**해야 합니다. 설정만 비우는 걸로는 이미 배포된
HTML 의 태그가 사라지지 않습니다.

| 도구 | 넣는 값 | 측정되는 것 | 쿠키 |
| --- | --- | --- | --- |
| Cloudflare Web Analytics | `cloudflareToken` | 방문자·유입경로 | 없음 |
| GA4 | `ga4Id` | 방문자·유입경로 + **쿠팡 클릭** | 있음 |

Cloudflare 는 페이지뷰만 셉니다. **쿠팡 클릭이 얼마나 나는지 보려면 GA4 가 필요합니다.**
둘 다 넣으면 둘 다 동작합니다.

보내는 이벤트 (GA4 기준):

- `recipe_open` — 어떤 레시피를, 바로 가능/대체/부족 중 어느 상태로 열었는지
- `shop_click` — 어떤 재료를, 상품카드/딥링크/검색 중 무엇으로 눌렀는지, 어느 레시피에서
- `app_install` — 홈 화면에 설치

측정 도구가 차단당하거나 실패해도 앱 동작에는 영향이 없습니다.

의존성이 없는 순수 HTML·CSS·JavaScript이고, 모듈이나 `fetch` 를 쓰지 않아
`file://` 로 열어도 (오프라인 캐시만 빼고) 똑같이 동작합니다.

**첫 로드는 47KB(gzip)** 입니다. 가장 큰 `data/coupang-products.js`(65KB)는
레시피 상세를 처음 열 때 받아옵니다. 받아오기 전에는 링크 칩만 보여주고,
도착하면 장보기 칸만 다시 그립니다. 못 받아도 칩으로 장보기는 됩니다.
서비스워커 캐시 목록에는 그대로 있어서 오프라인에서도 상품이 보입니다.

## 고칠 때

**레시피 추가** — `data/recipes.js` 에 객체 하나를 더합니다.

```js
{
  id: 'godeungeo-jorim', name: '고등어조림', category: '한식', kind: '국·찌개',
  time: 35, difficulty: '보통', servings: 2, veg: false,
  essential: ['고등어', '무', '고춧가루'],
  optional: ['양파', '대파', '청양고추', '간장', '설탕'],
  steps: ['...', '...', '...'],
  tip: '...'
}
```

같은 요리의 다른 버전이면 `family` 와 탭에 쓸 짧은 `label` 을 함께 넣습니다.
이때 그 버전을 규정하는 재료는 반드시 `essential` 에 넣어야 버전이 구분됩니다.
(참치 김치찌개의 `참치캔` 처럼)

```js
{ id: '...', family: '김치찌개', label: '참치', name: '참치 김치찌개', ... }
```

**대체 재료 추가** — `data/ingredients.js` 의 `SWAPS` 에 넣습니다.
특정 요리에서만 통하는 대체는 레시피 쪽에 `swaps: { '돼지고기': [{ use: '참치캔' }] }` 로 적으면
그 레시피에서는 전역 규칙 대신 이쪽이 쓰입니다.

**새 재료 이름** — `data/ingredients.js` 의 `INGREDIENT_CATEGORIES` 에도 넣어 주세요.
빠른 담기 목록과 자동완성에 함께 잡힙니다.

**파일을 고친 뒤** — `sw.js` 맨 위 `CACHE` 의 버전 숫자를 올려야
이미 설치한 사람에게 새 버전이 전달됩니다.
